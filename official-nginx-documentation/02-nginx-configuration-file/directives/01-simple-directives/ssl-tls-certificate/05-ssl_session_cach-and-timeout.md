# ssl_session_cache and ssl_session_timeout
---
# ۱-اول برایه فهم این دو دایرکتیو باید بدونید که `TLS Session Resumption` چیست؟

فرض کن یک کاربر وارد سایت `example.com` می‌شود.

وقتی مرورگر برای اولین بار به سرور Nginx متصل می‌شود، فرایند TLS Handshake انجام می‌شود.

در این فرایند:

- مرورگر و سرور نسخه TLS را مشخص می‌کنند.
    
- ا-Cipher Suite انتخاب می‌شود.
    
- احراز هویت سرور انجام می‌شود.
    
- کلیدهای لازم برای ارتباط امن ایجاد می‌شوند.
    

این فرایند هزینه پردازشی دارد، مخصوصاً برای سرورهایی که تعداد زیادی اتصال HTTPS دریافت می‌کنند.

حالا فرض کن همان کاربر چند لحظه بعد دوباره به سرور متصل شود.

آیا لازم است تمام مراحل Handshake از ابتدا انجام شوند؟

خیر! اینجا مفهوم Session Resumption مطرح می‌شود.

مرورگر می‌تواند از اطلاعات Session قبلی برای برقراری مجدد ارتباط استفاده کند و بخشی از مراحل Handshake را کاهش دهد.

برای مدیریت این قابلیت، دو Directive مورد بحث ما هستند.

---
## ۲-توضیح هر کدوم و محل قرارگیری انها

## ا-<mark>اولین دایرکتیو</mark>**ssl_session_cache**

### **تعریف**

این Directive برای ذخیره‌سازی اطلاعات TLS Session در حافظه Cache سرور Nginx استفاده می‌شود.

به کمک آن، Nginx می‌تواند اطلاعات Sessionهای قبلی را نگهداری کند تا در صورت اتصال مجدد کلاینت، امکان استفاده مجدد از آن‌ها فراهم شود.

### **محل قرارگیری**

در دو Context قابل استفاده است:

- `http`
    
- `server`
    

### **ساختار**

```
ssl_session_cache shared:SSL:10m;
```

بیایید پارامترهای آن را بررسی کنیم:

|پارامتر|توضیح|
|---|---|
|`shared`|Cache مشترک بین Worker Processها|
|`SSL`|نامی که برای Cache انتخاب کرده‌ایم|
|`10m`|حجم حافظه اختصاص‌یافته به Cache، برابر ۱۰ مگابایت|

### **چرا shared اهمیت دارد؟**

فرض کن Nginx چهار Worker Process دارد:

	<img src="../../00-images/ssl_sessioncache-share.png" alt="images" width=800>
</p>


اگر Cache از نوع `shared` نباشد و از Cache داخلی OpenSSL استفاده کنیم، هر Worker Cache مخصوص خودش را خواهد داشت.

اما با `shared`، تمام Workerها به یک حافظه مشترک دسترسی دارند.

طبق مستندات Nginx، <mark>هر یک مگابایت Shared Cache تقریباً ظرفیت ۴۰۰۰ Session را دارد.</mark>


===

## ا-<mark>دومین دایرکتیو</mark>**ssl_session_timeout**

### **تعریف**

این Directive مشخص می‌کند اطلاعات یک TLS Session چه مدت می‌توانند برای استفاده مجدد معتبر باشند.

ساختار:

```
ssl_session_timeout 10m;
```

در این مثال، مدت اعتبار Session برابر ۱۰ دقیقه است.

یعنی اگر کلاینت بخواهد از Session قبلی استفاده کند، باید در بازه زمانی مجاز اقدام کند.

مقدار پیش‌فرض این Directive در Nginx برابر ۵ دقیقه است.

### **پارامترهای زمانی**

می‌توانیم از واحدهای زمانی مختلف استفاده کنیم:

```
ssl_session_timeout 10m;
ssl_session_timeout 30m;
ssl_session_timeout 1h;
ssl_session_timeout 1d;
```

محل قرارگیری آن نیز مانند Directive قبلی در Contextهای `http` و `server` است.
