# server_name
---
## ۱-دایرکتیو server_name چیست؟

دستور **server_name** مشخص می‌کند **کدام نام دامنه به این بلاک server مربوط است.** این دستور هم مثل listen یک **Simple Directive** است و داخل بلاک server نوشته می‌شود.

---
## ۲-چرا به server_name نیاز داریم:

فرض کن دو سایت روی **یک سرور، یک IP و یک پورت** داری:

```
server {
    listen 80;
    server_name first.com;

    root /var/www/first;
}

server {
    listen 80;
    server_name second.com;

    root /var/www/second;
}
```

وقتی کاربر `http://first.com` را باز می‌کند، مرورگر نام دامنه را در هدر `Host` درخواست می‌فرستد:

```
Host: first.com
```

ا-Nginx از بین بلاک‌های مربوط به IP و پورت دریافت‌کننده، بلاکی را انتخاب می‌کند که `server_name` آن با این نام مطابقت دارد؛ اینجا بلاک اول.

---
## ۳-یه نکته میتونی چند تا نام برایه یک سایت بزاری 

**می‌توانی چند نام هم برای یک سایت بنویسی:**

```
server_name example.com www.example.com;
```

یعنی هر دو نام به همین بلاک مربوط‌اند.

**نکتهٔ مهم:** نوشتن دامنه در `server_name`، تنظیم DNS را انجام نمی‌دهد. باید جداگانه DNS دامنه را هم تنظیم کنی تا به آدرس سرورت برسد.

---
## ۴-دامنه یا اسم سرور چیه 

**اسمی که کاربر در مرورگر وارد می‌کند تا سایتت را باز کند، «دامنه» است**؛ مثلاً:

```
example.com
```

ما همان دامنه را در Nginx جلوی دستور **`server_name`** می‌نویسیم:

```
server_name example.com;
```

یعنی: **«درخواست‌هایی که برای دامنهٔ `example.com` می‌آیند، مربوط به این بلاک `server` هستند.»**
