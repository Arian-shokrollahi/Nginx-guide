# listen 
---
## ۱-دایرکتیو listen چیست؟

ا-**«`listen` یک Simple Directive است که مشخص می‌کند Nginx برای دریافت اتصال‌ها روی چه آدرس IP و پورتی گوش بدهد.»**

---
## ۲-دایرکتیو listen درون کجا استفاده میشه
- دایرکتیو ها که گفتیم درون فایل هایه کانفیگ استفاده میشن -ـ- این که دیگه پرسیدن نداره ولی اگر بخواهیم به مکانی که دایرکتیو listen درون اون قرار داره اشاره کنیم :
-  دستور **`listen` داخل بلاک `server`** نوشته می‌شود:

```
http {
    server {
        listen 80;
    }
}
```
- این یعنی سرور رویه پورت ۸۰ اماده اتصال است

---

## ۳- وظیفه ی دایرکتیو listen  چیست ؟

**دستور `listen` مشخص می‌کند Nginx برای آن بلاک `server`، روی چه IP و پورتی آمادهٔ دریافت اتصال‌های ورودی باشد.**

```
listen 192.168.1.10:80;
```

یعنی روی IP برابر با `192.168.1.10` و پورت `80` منتظر اتصال باشد.

---

## ۴-حالا بریم یه نمونه از محیط پرداکشنی رو ببینیم

فرض کن روی یک سرور واقعی، **سایت عمومی** و یک **پنل داخلی** داری.

**سایت عمومی** باید از طریق IPهای سرور، روی پورت ۸۰ درخواست دریافت کند:

```
server {
    listen 80;
    server_name example.com;

    root /var/www/example;
    index index.html;
}
```

اینجا محدودیت خاصی برای IP نداریم، پس فقط پورت را نوشته‌ایم.

**پنل داخلی** باید فقط از طریق IP شبکهٔ داخلی سرور، یعنی `192.168.1.10`، در دسترس باشد:

```
server {
    listen 192.168.1.10:8080;
    server_name panel.internal;

    root /var/www/panel;
    index index.html;
}
```

اینجا IP را مشخص کرده‌ایم تا این پنل **روی آدرس شبکهٔ داخلی و پورت ۸۰۸۰** اتصال دریافت کند. این IP باید روی خودِ سرور تنظیم شده باشد.

|سرویس|تنظیم `listen`|محل دریافت اتصال|
|---|---|---|
|سایت عمومی|`listen 80;`|تمام IPهای IPv4 سرور، پورت ۸۰|
|پنل داخلی|`listen 192.168.1.10:8080;`|فقط IP مشخص‌شده، پورت ۸۰۸۰|

برای محدودکردن دسترسی پنل به افراد یا شبکه‌های مجاز، فایروال و احراز هویت را هم تنظیم می‌کنیم.
