# 1-block directive http
---
## ۰-بلوک دایرکتیو برایه چیست؟

بلوک **`http` محیط اصلی تنظیمات وب در nginx است**. داخل آن مشخص می‌کنیم سایت‌ها چگونه درخواست‌های HTTP و HTTPS را پردازش کنند.

**۱. جای `http` در فایل تنظیمات**

بلوک `http` در سطح اصلی تنظیمات قرار می‌گیرد؛ کنار `events`، نه داخل آن:

```
worker_processes auto;

events {
    worker_connections 768;
}

http {
    # تنظیمات وب

    server {
        listen 8080;

        location /images/ {
            root /var/www;
        }
    }
}
```

|بخش|مسئولیت|
|---|---|
|`events`|مدیریت اتصال‌ها|
|`http`|تنظیمات کلی سرویس وب|
|`server`|تنظیمات یک سایت|
|`location`|تنظیمات مسیرهای درخواست در آن سایت|

**۲. چه چیزهایی داخل `http` می‌نویسیم؟**

دستورهای ساده، بلوک‌های مجاز و دستورهای `include`. مثلاً:

```
http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    sendfile on;
    gzip on;

    access_log /var/log/nginx/access.log;
    error_log /var/log/nginx/error.log;

    include /etc/nginx/conf.d/*.conf;
    include /etc/nginx/sites-enabled/*;
}
```

|دستور|کاربرد|
|---|---|
|`include /etc/nginx/mime.types;`|خواندن ارتباط پسوند فایل‌ها با نوع محتوا؛ مثل `.png` با `image/png`|
|`default_type`|نوع پیش‌فرض پاسخ وقتی نوع فایل مشخص نیست|
|`sendfile on;`|استفاده از قابلیت سیستم‌عامل برای ارسال فایل|
|`gzip on;`|فعال کردن فشرده‌سازی برای پاسخ‌های مناسب|
|`access_log`|ثبت درخواست‌ها و اطلاعات پاسخ|
|`error_log`|ثبت خطاها|
|دو `include` آخر|خواندن فایل‌های تنظیمات سایت‌ها|

**۳. تنظیمات مشترک و ارث‌بری**

بسیاری از تنظیمات داخل `http` به `server`ها و `location`های زیرمجموعه منتقل می‌شوند، مگر اینکه در سطح پایین‌تر تغییر داده شوند.

مثلاً:

```
http {
    client_max_body_size 10m;

    server {
        listen 8080;
        # محدودیت بدنهٔ درخواست: 10m
    }

    server {
        listen 8081;
        client_max_body_size 20m;
        # محدودیت این سرور: 20m
    }
}
```

یعنی مقدار عمومی **۱۰ مگابایت** است، ولی سرور دوم مقدار اختصاصی **۲۰ مگابایت** دارد.

**نکتهٔ مهم:** قواعد ارث‌بری برای همهٔ دستورها یکسان نیست؛ نباید فرض کنی همهٔ تنظیمات همیشه با هم جمع می‌شوند.

**۴. نکاتی که باید حواست به آن‌ها باشد**

- ا-**`http` خودش پورت تعیین نمی‌کند.** پورت سایت را با `listen` داخل `server` مشخص می‌کنی.


- **برای هر سایت `http` جدید نساز.** در ساختار معمول، چند `server` داخل همان `http` قرار می‌گیرند.


- **هر دستور جای مجاز خودش را دارد.** مثلاً `server_name` داخل `server` است؛ `worker_processes` در سطح اصلی تنظیمات است.


- **وجود `http` به معنی نبود HTTPS نیست.** تنظیمات HTTPS هم داخل `server`های همین بلوک قرار می‌گیرند.

- **خط‌های شروع‌شده با `#` کامنت‌اند** و اجرا نمی‌شوند.

- **دستور ساده با `;` تمام می‌شود** و دستور بلوکی با `{ }` نوشته می‌شود.

بعد از تغییر تنظیمات، اول تست کن:

```
sudo nginx -t
```

اگر تست موفق بود و nginx در حال اجرا بود، تغییرات را اعمال کن:

```
sudo systemctl reload nginx
```
