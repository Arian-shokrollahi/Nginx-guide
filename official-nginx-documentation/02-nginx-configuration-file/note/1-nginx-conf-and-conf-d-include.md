# 1-فرقه بین nginx.conf و conf.d
ا-**`nginx.conf` یک فایل است، ولی `conf.d` یک پوشه است.** فایل اصلی، تنظیمات داخل آن پوشه را با دستور `include` می‌خواند.

|مورد|چیست؟|نقش|
|---|---|---|
|`/etc/nginx/nginx.conf`|فایل اصلی تنظیمات|تنظیمات کلی nginx و مشخص کردن فایل‌های دیگری که باید خوانده شوند|
|`/etc/nginx/conf.d/`|پوشهٔ تنظیمات|نگهداری فایل‌های جداگانه، مثلاً تنظیمات هر سایت|
|`/etc/nginx/conf.d/bilk.conf`|یک فایل داخل آن پوشه|تنظیمات سروری که عکس تو را سرو می‌کند|

**چرا تنظیمات را جدا می‌کنیم؟**

فرض کن سه سایت داری: فروشگاه، وبلاگ و سایت تصاویر. می‌توانی هر سه بلوک `server` را داخل `nginx.conf` بنویسی؛ اما فایل اصلی طولانی می‌شود و پیدا کردن تنظیمات هر سایت سخت‌تر خواهد شد.

پس برای هرکدام یک فایل جدا می‌سازی:

|فایل|محتوای آن|
|---|---|
|`conf.d/shop.conf`|تنظیمات فروشگاه|
|`conf.d/blog.conf`|تنظیمات وبلاگ|
|`conf.d/bilk.conf`|تنظیمات سرور تصاویر|

این جداسازی برای **نظم و مدیریت راحت‌تر** است. همهٔ این فایل‌ها در نهایت بخشی از تنظیمات همان nginx هستند.

**دستور `include` چه کار می‌کند؟**

در فایل اصلی می‌نویسیم:

```
http {
    include /etc/nginx/conf.d/*.conf;
}
```

معنی این خط:

> «تمام فایل‌های داخل `/etc/nginx/conf.d/` که نامشان با `.conf` تمام می‌شود را بخوان و تنظیماتشان را همین‌جا وارد کن.»

- `*` یعنی هر نامی.
- `.conf` یعنی فقط فایل‌هایی با این پسوند.
- **محل نوشتن `include` مشخص می‌کند محتوا در چه محیطی خوانده شود.**

در این مثال، `include` داخل `http` است؛ بنابراین محتوای فایل‌ها هم در محیط `http` خوانده می‌شود.

**مثال با فایل خودت**

داخل `nginx.conf`:

```
events {
    worker_connections 768;
}

http {
    include /etc/nginx/conf.d/*.conf;
}
```

داخل `conf.d/bilk.conf`:

```
server {
    listen 8080;
    server_name localhost;

    location /images/ {
        root /var/www;
    }
}
```

nginx این ترکیب را **از نظر ساختار تنظیمات** مانند این می‌خواند:

```
events {
    worker_connections 768;
}

http {
    server {
        listen 8080;
        server_name localhost;

        location /images/ {
            root /var/www;
        }
    }
}
```

فایل‌ها واقعاً به هم چسبانده یا بازنویسی نمی‌شوند؛ nginx هنگام خواندن تنظیمات، محتوای فایل دوم را در محل `include` پردازش می‌کند.

**دو نکتهٔ مهم:**

- پوشهٔ `conf.d` به‌خودی‌خود فعال نیست؛ **این خط `include` است که باعث خواندن فایل‌هایش می‌شود**. اگر خط را حذف کنی و جای دیگری آن فایل‌ها را وارد نکرده باشی، تنظیماتشان خوانده نمی‌شود.
- در `bilk.conf` دوباره `http` نمی‌نویسی، چون فایل از داخل `http` وارد شده است. فقط `server` را می‌نویسی.

بعد از ذخیرهٔ تغییرات، برای بررسی تنظیمات:

```
sudo nginx -t
```

و اگر تست موفق بود، برای اعمال آن‌ها در nginx در حال اجرا:

```
sudo systemctl reload nginx
```

# دلیل استفاده از include  و هدف از تشکیل فولدر conf.d

هدف **جدا کردن تنظیمات سایت‌ها برای مدیریت راحت‌تر** است.

مثلاً به‌جای نوشتن تنظیمات ۱۰ سایت در یک فایل بزرگ `nginx.conf`، برای هر سایت یک فایل داخل `conf.d` می‌سازیم. این‌طوری پیدا کردن، ویرایش و بررسی تنظیمات هر سایت آسان‌تر می‌شود.

ا-**`include` این فایل‌های جدا را وارد تنظیمات اصلی می‌کند** تا nginx همه را بخواند.

پس `nginx.conf` تنظیمات کلی را نگه می‌دارد و فایل‌های `conf.d` تنظیمات جداگانهٔ سایت‌ها را.

# هدف درست کردن فولدر conf.d
 **هدف اصلی این ساختار، نظم دادن و راحت‌تر کردن مدیریت تنظیمات است**.

به‌جای یک فایل بزرگ، تنظیمات را در چند فایل کوچک داخل `conf.d` نگه می‌داریم و با `include` می‌خوانیم.

فقط یادت باشد: **وجود پوشهٔ `conf.d` اجباری نیست و خودش کاری انجام نمی‌دهد؛ دستور `include` باعث خواندن فایل‌های آن می‌شود.** این فایل‌ها می‌توانند تنظیمات سایت‌ها یا تنظیمات مشترک وب باشند.
