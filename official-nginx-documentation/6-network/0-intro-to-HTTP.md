## 1. HTTP چیست؟

ا-HTTP مخفف این عبارته:

ا-Hypertext Transfer Protocol

یعنی «پروتکل انتقال ابرمتن».

به زبان ساده، HTTP مجموعه‌ای از قوانین برای ارتباط بین Client و Server هست.

مثلاً وقتی داخل مرورگر این آدرس رو وارد می‌کنی:

```
http://example.com/products
```

### دو مفهموم مهم داریم ما درون HTTP:

- ا-HTTP Request: درخواستی که کلاینت ارسال می‌کنه.
- ا-HTTP Response: پاسخی که سرور به کلاینت برمی‌گردونه

---

## 2-ساختار HTTP Request

فرض کن مرورگر درخواست زیر رو ارسال می‌کنه:

```
GET /products HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
```

این درخواست شامل بخش‌های مختلفیه.

### A. Request Line

```
GET /products HTTP/1.1
```

| قسمت        | معنی                     |
| ----------- | ------------------------ |
| `GET`       | متد درخواست              |
| `/products` | مسیر مورد درخواست (Path) |
| `HTTP/1.1`  | نسخه پروتکل              |

---

## 3-ساختار HTTP Response

بعد از اینکه سرور درخواست رو دریافت کرد، یک Response برمی‌گردونه.

مثلاً:

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 27

{"name":"Ali","age":25}
```

سه بخش مهم داره:

| بخش              | نمونه                            | کاربرد        |
| ---------------- | -------------------------------- | ------------- |
| Status Line      | `HTTP/1.1 200 OK`                | نتیجه درخواست |
| Response Headers | `Content-Type: application/json` | اطلاعات پاسخ  |
| Response Body    | `{"name":"Ali","age":25}`        |               |

---

### 4-HTTP Methods

ا-Method مشخص می‌کنه کلاینت قصد انجام چه عملی رو داره.

|Method|کاربرد معمول|
|---|---|
|`GET`|دریافت اطلاعات|
|`POST`|ارسال داده برای پردازش یا ایجاد منبع|
|`PUT`|ایجاد یا جایگزینی وضعیت یک منبع|
|`PATCH`|تغییر بخشی از یک منبع|
|`DELETE`|درخواست حذف منبع|
|`HEAD`|دریافت Headerهای پاسخ بدون Body|
|`OPTIONS`|بررسی گزینه‌های ارتباطی موجود|

مثلاً در یک API:

```
GET /users
POST /users
GET /users/10
DELETE /users/10
```

این درخواست‌ها هرکدوم هدف متفاوتی دارن، هرچند Backend تعیین می‌کنه واقعاً چه عملی اجرا بشه.

### 5- HTTP Status Codes

سرور با Status Code مشخص می‌کنه نتیجه درخواست چی بوده.

|کد|معنی|
|---|---|
|`200 OK`|درخواست موفق|
|`201 Created`|منبع ایجاد شد|
|`301 Moved Permanently`|انتقال دائمی|
|`302 Found`|تغییر مسیر موقت|
|`400 Bad Request`|درخواست نامعتبر|
|`401 Unauthorized`|احراز هویت لازم است|
|`403 Forbidden`|دسترسی ممنوع|
|`404 Not Found`|منبع پیدا نشد|
|`500 Internal Server Error`|خطای داخلی سرور|
|`502 Bad Gateway`|پاسخ نامعتبر از Upstream|
|`503 Service Unavailable`|سرویس در دسترس نیست|
|`504 Gateway Timeout`|پاسخ Upstream به‌موقع دریافت نشد|

این چهار مورد آخر، مخصوصاً `502` و `504`، در عیب‌یابی Nginx خیلی به کارت میان.

---
### 6. تفاوت HTTP و HTTPS

HTTP به‌تنهایی ارتباط رو رمزنگاری نمی‌کنه.

HTTPS همون HTTP هست که از ارتباط رمزنگاری‌شده با TLS استفاده می‌کنه.

|ویژگی|HTTP|HTTPS|
|---|---|---|
|رمزنگاری ارتباط|خیر|بله|
|پورت پیش‌فرض متداول|80|443|
|حفاظت از داده در مسیر انتقال|ندارد|دارد|
|اعتبارسنجی هویت سرور|ندارد|با گواهی TLS|

HTTPS به‌خودی‌خود تضمین نمی‌کنه یک وب‌سایت قابل اعتماد یا بدون آسیب‌پذیری باشه.
