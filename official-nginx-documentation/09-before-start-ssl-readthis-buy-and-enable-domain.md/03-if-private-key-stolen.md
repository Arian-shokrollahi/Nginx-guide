## ۱. اگر Private Key سرقت شود چه اتفاقی می‌افتد؟

فرض کن وب‌سایت تو این دامنه را دارد:

```
https://shokbil.ir
```

و مهاجم به این دو فایل دسترسی پیدا کرده است:

```
fullchain.pem
privkey.pem
```

از آنجا که Certificate عمومی است، مشکل اصلی سرقت Private Key است.

مهاجم ممکن است بتواند:

۱. جعل هویت وب‌سایت (Impersonation)

مهاجم می‌تواند روی یک سرور دیگر از Certificate و Private Key سرقت‌شده استفاده کند و خودش را به‌جای وب‌سایت تو معرفی کند.

اگر بتواند ترافیک کاربران را به سرور خودش هدایت کند، ممکن است مرورگر Certificate را معتبر تشخیص دهد.

۲. حمله Man-in-the-Middle

اگر مهاجم بتواند ارتباط کاربر و سرور را رهگیری یا منحرف کند، سرقت Private Key می‌تواند به او در جعل هویت سرور کمک کند.

۳. کلاهبرداری و فیشینگ

مهاجم می‌تواند یک نسخه جعلی از سایت تو بسازد و از اعتبار هویت دامنه برای فریب کاربران استفاده کند؛ مثلاً کاربران را به واردکردن نام کاربری و رمز عبور ترغیب کند.

## ۲. آیا می‌تواند اطلاعات قبلی کاربران را رمزگشایی کند؟

اینجا یک نکته تخصصی TLS داریم!

در TLS مدرن، مثل TLS 1.3 و TLS 1.2 با الگوریتم‌های ECDHE، قابلیت Forward Secrecy وجود دارد.

یعنی حتی اگر مهاجم Private Key را سرقت کند، معمولاً نمی‌تواند ترافیک رمزنگاری‌شده قبلی را که ضبط کرده است رمزگشایی کند.

پس سرقت Private Key به معنی دسترسی خودکار به اطلاعات دیتابیس یا رمزهای عبور کاربران نیست.

## ۳. اگر Private Key سرقت شد چه کار کنیم؟

|اقدام|هدف|
|---|---|
|Revoke Certificate|باطل‌کردن گواهی قبلی|
|Generate New Private Key|تولید کلید خصوصی جدید|
|Issue New Certificate|دریافت Certificate جدید|
|Replace Old Certificate|جایگزینی فایل‌های قبلی|
|Reload Nginx|بارگذاری تنظیمات جدید|
|Security Audit|بررسی نفوذ و دسترسی‌های غیرمجاز|

نکته امنیتی

اگر احتمال سرقت Private Key وجود دارد، نباید فقط فایل قبلی را حذف کنیم؛ باید گواهی قبلی را نیز باطل کنیم و کلید جدید بسازیم.

## ۴. جمع‌بندی برای جزوه‌ات

- ا-Certificate عمومی است و می‌توان آن را در اختیار کاربران قرار داد.
    
- ا-Private Key محرمانه است و باید فقط روی سرور امن نگهداری شود.
    
- سرقت Private Key می‌تواند امکان جعل هویت سرور را فراهم کند.
    
- مهاجم با این کلید به‌صورت خودکار به دیتابیس یا اطلاعات کاربران دسترسی پیدا نمی‌کند.
    
- برای جلوگیری از سوءاستفاده باید Certificate قبلی را باطل و گواهی جدید با Private Key جدید صادر کنیم.
    

یک نکته را همیشه به خاطر بسپار: امنیت HTTPS فقط به داشتن Certificate وابسته نیست؛ حفاظت از Private Key یکی از پایه‌های اصلی امنیت TLS است.
