# Round Robin
- در این قسمت قراره درمورد چی صحبت کنیم ؟
ا-Weighted Round Robin: توزیع چرخشی درخواست‌ها بر اساس وزن تعیین‌شده برای هر Backend.

---
### ۱- Round Robin یعنی چی :

ا-Round Robin یعنی Nginx درخواست‌ها را به‌صورت چرخشی بین Backendها توزیع می‌کند تا سهم درخواست‌ها در حالت عادی تقریباً برابر باشد.

---

## ۲- فلسفه Round Robin چیست :

فلسفه Round Robin این است که درخواست‌های ورودی به‌صورت چرخشی بین Backendهای تعریف‌شده در گروه `upstream` توزیع شوند تا سهم هر Backend از درخواست‌ها در شرایط عادی تقریباً برابر باشد.

برای مثال، اگر سه Backend داشته باشیم، ترتیب توزیع به این صورت خواهد بود:

```
Request 1, 2  → Backend 1
Request 3, 4  → Backend 2
Request 5, 6  → Backend 3

Request 7, 8  → Backend 1
Request 9, 10 → Backend 2
Request 11,12 → Backend 3
```

نکته: Round Robin به معنی تقسیم دو‌تایی درخواست‌ها نیست؛ هر درخواست به نوبت به Backend بعدی ارسال می‌شود. تعداد درخواست‌ها در نهایت بین Backendها تقریباً برابر خواهد بود، مشروط بر اینکه وزن‌ها برابر باشند و سرورها از چرخه خارج نشده باشند.

---

## ۳- این قابلیت درکدام و توسط کدام بلاک ایجاد میشه:

قابلیت توزیع درخواست‌ها بین چند Backend توسط بلاک `upstream` فراهم می‌شود.

در Nginx دو روش برای تعریف Round Robin با سهم برابر داریم:

روش اول: بدون تعریف Weight

```
upstream app_backend {
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
    server 127.0.0.1:3003;
}
```

در این حالت Nginx به‌صورت پیش‌فرض برای تمام سرورها `weight=1` در نظر می‌گیرد.

روش دوم: تعریف Weight برابر

```
upstream app_backend {
    server 127.0.0.1:3001 weight=1;
    server 127.0.0.1:3002 weight=1;
    server 127.0.0.1:3003 weight=1;
}
```

نتیجه هر دو روش یکسان است.

نکته‌ای که برای یادداشت GitHub مهم است:

- ا-`upstream`: گروهی از Backendها را تعریف می‌کند.
    
- ا-`weight`: سهم نسبی هر Backend از توزیع درخواست‌ها را مشخص می‌کند.
    
- ا-Round Robin: الگوریتم پیش‌فرض توزیع درخواست‌ها در Upstream است.
    

پس لازم نیست برای فعال‌کردن Round Robin چیزی بنویسی؛ Nginx خودش آن را به‌صورت پیش‌فرض اجرا می‌کند

## ۴- چند حالت دارد این قابلیت 
#### ما میتونیم به ۳ روش این قابلیت رو ایجاد کنیم

- ا-<mark>(تقسیم یکی یکی درخواست ها بین بک اند ها)1</mark>یک بیایم در block upstream  بک اند هارو + IP + Port تعریف کنیم و کار دیگه ای نکنیم
بدون تعریف Weight

```
upstream app_backend {
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
    server 127.0.0.1:3003;
}
```

- ا-<mark>2(تقسیم یکی یکی درخواست ها بین بک اند ها)</mark> دو بیایم در block upstream  
- ای پی Ip
- پورت Port
-  و از دایرکتیو weight استفاده کنیم و یک بزاریم

```
upstream app_backend {
    server 127.0.0.1:3001 weight=1;
    server 127.0.0.1:3002 weight=1;
    server 127.0.0.1:3003 weight=1;
}
```

- ا-<mark> 3(تقسیم ۲ تا n بار بین سرور هایه بک اند)</MARK> سه بیایم ۲ تا N درخواست رو تقسیم کنیم بین سرور هایه بک اند
```
upstream app_backend {
    server 127.0.0.1:3001 weight=2-N;
    server 127.0.0.1:3002 weight=2-N;
    server 127.0.0.1:3003 weight=2-N;
}
```
