# ا-1. backup چیست؟

پارامتر `backup` به ما اجازه می‌دهد یک یا چند Backend Server را به‌عنوان سرور پشتیبان (Backup Server) تعریف کنیم.

یعنی چه؟

فرض کن سه سرور Backend داریم:

- Server 1
    
- Server 2
    
- Server 3
    

می‌خواهیم در حالت عادی فقط Server 1 و Server 2 درخواست دریافت کنند و Server 3 فقط زمانی وارد چرخه توزیع شود که سرورهای اصلی در دسترس نباشند.

اینجاست که از `backup` استفاده می‌کنیم.

# 2. ساختار و Syntax

ا-`backup` یک پارامتر از Directive مربوط به `server` است که داخل بلاک `upstream` استفاده می‌شود.

```
upstream backend {

    server 192.168.1.10:80;
    server 192.168.1.11:80;

    server 192.168.1.12:80 backup;

}
```

در این مثال:

|سرور|وضعیت|
|---|---|
|192.168.1.10|Primary|
|192.168.1.11|Primary|
|192.168.1.12|Backup|

دو سرور اول در حالت عادی درخواست دریافت می‌کنند و سرور سوم نقش پشتیبان دارد.

# 4. تفاوت Backup با Weight

این دو را با هم اشتباه نگیر.

|ویژگی|weight|backup|
|---|---|---|
|کاربرد|تعیین سهم سرور|تعیین سرور پشتیبان|
|فعالیت در حالت عادی|بله|خیر|
|اولویت‌بندی|بله|نقش پشتیبان|
|هدف اصلی|توزیع بار|افزایش دسترس‌پذیری|

# 5. اهمیت در محیط Production

فرض کن یک فروشگاه اینترنتی داری و دو سرور اصلی مسئول پاسخ‌گویی به کاربران هستند.

اگر هر دو سرور اصلی از دسترس خارج شوند، سرور Backup می‌تواند به ادامه ارائه سرویس کمک کند.

البته به شرطی که خودش سالم باشد و نسخه مناسبی از سرویس و داده‌ها را در اختیار داشته باشد.

نکته فنی مهم: در Nginx Open Source، سرور Backup زمانی وارد چرخه می‌شود که سرورهای غیر Backup در دسترس نباشند. تشخیص خرابی معمولاً بر اساس سازوکار Passive Health Check انجام می‌شود، نه بررسی دائمی سلامت سرورها.

همچنین `backup` با الگوریتم‌های `ip_hash` و `hash` سازگار نیست و در نسخه متن‌باز نمی‌توان آن را با این دو روش به این شکل ترکیب کرد.
