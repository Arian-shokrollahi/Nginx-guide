# proxy_read_timeout time; 
---
## 1-این دایرکتیو چیکار میکند:

ا-`proxy_read_timeout` حداکثر فاصله زمانی مجاز بین دو عملیات متوالی خواندن داده از Backend را مشخص می‌کند.

مثلاً:

```
proxy_read_timeout 30s;
```

یعنی اگر Nginx به مدت ۳۰ ثانیه هیچ داده‌ای از Backend دریافت نکند، Timeout رخ می‌دهد.

نکته: این ۳۰ ثانیه زمان کل پاسخ نیست؛ فاصله زمانی بین دریافت داده‌هاست.

---

## 2- ساختارش به چه صورته و در کدام بلاک قرار میگیرد

ساختار دستور `proxy_read_timeout` به این صورت است:

```
proxy_read_timeout time;
```

Contextهای مجاز:

- `http`
    
- `server`
    
- `location`
    

معمولاً کجا تعریف می‌شود؟

معمولاً داخل بلاک `location` و در کنار سایر تنظیمات مربوط به `proxy_pass` قرار می‌گیرد.

مثال:

```
server {
    listen 80;

    location / {
        proxy_pass http://127.0.0.1:8082;

        proxy_connect_timeout 5s;
        proxy_read_timeout 30s;
    }
}
```

---
## 3-اهمیت ان در محیط پروداکشن چقدره

### چرا اهمیت دارد؟

1. جلوگیری از انتظار بی‌نهایت: اگر Backend پاسخ ندهد، Nginx برای همیشه منتظر نمی‌ماند.

2. مدیریت منابع: از معطل ماندن طولانی ارتباطات Proxy جلوگیری می‌کند.

3. مدیریت سرویس‌های کند: به شما اجازه می‌دهد زمان انتظار متناسب با نوع پردازش Backend را تنظیم کنید.

4. کنترل خطاهای Gateway Timeout: مشخص می‌کند Nginx چه زمانی به دلیل نرسیدن داده از Backend ارتباط را خاتمه دهد.
