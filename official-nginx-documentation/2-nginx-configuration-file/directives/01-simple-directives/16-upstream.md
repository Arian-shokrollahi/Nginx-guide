# ا-1. upstream چیست؟

- توضیح ساده: به شما اجازه میده گروه بک اندیتون رو توسط IP + Port که داره انتخاب کنید و   حالا با directive  هایه دیگه شما میتونید اون الگوریتم هارو پیاده کنید
- مثل مثلا دایرکتیو weight:`weight` هم یکی از پارامترهای مهم در Load Balancing است؛ اما یک تفاوت فنی دارد:
ا-`weight` یک پارامتر (Parameter) از Directive مربوط به `server` است، نه یک Directive مستقل.

مثلاً:

ا-`upstream` در Nginx به ما اجازه می‌دهد چندین Backend Server را در قالب یک گروه تعریف کنیم تا Nginx بتواند درخواست‌های ورودی را بین آن‌ها توزیع کند.

به زبان ساده:

فرض کن سه وب‌سرور داریم که همگی یک سرویس را ارائه می‌دهند. به‌جای اینکه در تنظیمات `proxy_pass` برای هر سرور جداگانه آدرس بنویسیم، همه آن‌ها را داخل یک گروه به نام `backend` قرار می‌دهیم.

## 2. ساختار و Syntax

ساختار کلی این Directive به شکل زیر است:

```
upstream backend {
    server 192.168.1.10:80;
    server 192.168.1.11:80;
    server 192.168.1.12:80;
}
```

اجازه بده قسمت‌های مختلفش را بررسی کنیم:

- ا-`upstream`: دستور تعریف گروه Backendها
    
- ا-`backend`: نام دلخواهی که برای گروه انتخاب می‌کنیم.
    
- ا-`server`: معرفی هر Backend Server
    
- `192.168.1.10:80`: آدرس IP و پورت سرور مقصد
    

نکته: نام `backend` اجباری نیست و می‌توانیم نام‌هایی مثل `myapp` یا `web_servers` هم انتخاب کنیم.

## 3. جایگاه upstream در کانفیگ Nginx

این Directive باید در Context مربوط به `http` تعریف شود، نه داخل `server` یا `location`.

مثال کامل:

```
http {

    upstream backend {
        server 192.168.1.10:80;
        server 192.168.1.11:80;
        server 192.168.1.12:80;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://backend;
        }
    }

}
```

اینجا دو اتفاق مهم می‌افتد:

اتفاق اول:

```
upstream backend {
    server 192.168.1.10:80;
    server 192.168.1.11:80;
    server 192.168.1.12:80;
}
```

ما سه سرور Backend را در یک گروه به نام `backend` ثبت کردیم.

اتفاق دوم:

```
proxy_pass http://backend;
```

به Nginx می‌گوییم درخواست‌های دریافتی را به گروهی با نام `backend` ارسال کند.

حالا Nginx می‌تواند بر اساس الگوریتم انتخاب‌شده، درخواست‌ها را بین سرورهای این گروه توزیع کند.

---

## 4- اهمیت upstream در محیط Production چقدر است؟

ا-`upstream` یکی از اجزای اصلی معماری Load Balancing در Nginx است، چون:

1. مدیریت چندین Backend را ساده‌تر می‌کند.
    
2. امکان استفاده از الگوریتم‌های مختلف توزیع بار را فراهم می‌کند.
    
3. امکان تعریف تنظیمات اختصاصی برای هر Backend را می‌دهد.
    
4. باعث می‌شود در صورت اضافه یا حذف شدن سرورها، ساختار اصلی `proxy_pass` تغییر نکند.
    

---

## 5. یک نکته مهم

خود `upstream` به‌تنهایی الگوریتم Load Balancing نیست؛ بلکه یک گروه از سرورهای مقصد را تعریف می‌کند.

مثلاً:

```
upstream backend {
    least_conn;

    server 192.168.1.10;
    server 192.168.1.11;
    server 192.168.1.12;
}
```

اینجا `upstream` گروه را تعریف می‌کند و `least_conn` الگوریتم انتخاب سرور را مشخص می‌کند.
