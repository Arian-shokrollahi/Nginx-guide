# reverse proxy philosophy
# فلسفه پروکسی معکوس
1- اول قسمت هایه وب اپلیکیشن رو مورد برسی قرار میدهیم
۲- فلسفه ی اینکه چرا ما از reverse proxy استفاده میکنیم
۳- شبکه بک اند و ریورس پروکسی از دید کلاینت

------------
## 1- اینکه یک وب ابلیکیشن رو میشه به چند بخش تقسیم کرد
- اول این قسمت رو خوب باید درک کنید

```
        1. CLIENT
       (مرورگر کاربر)
             |
             v
       2. WEB SERVER
           (Nginx)
             |
             v
       3. BACKEND
      (Python / Node.js)
             |
             v
       4. DATABASE
     (MySQL / PostgreSQL)
```

### وظیفه هر بخش چیه؟

|بخش|وظیفه|مثال|
|---|---|---|
|Client|ارسال درخواست و نمایش سایت|Chrome|
|Frontend|ظاهر و رابط کاربری سایت|HTML, CSS, JS, React|
|Web Server / Reverse Proxy|دریافت و هدایت درخواست|Nginx|
|Backend|پردازش منطق برنامه|Python, Node.js|
|Database|ذخیره و بازیابی اطلاعات|MySQL, PostgreSQL|
### وظیفه هر بخش چیه؟

| بخش                        | وظیفه                      | مثال                 |
| -------------------------- | -------------------------- | -------------------- |
| Client                     | ارسال درخواست و نمایش سایت | Chrome               |
| Frontend                   | ظاهر و رابط کاربری سایت    | HTML, CSS, JS, React |
| Web Server / Reverse Proxy | دریافت و هدایت درخواست     | Nginx                |
| Backend                    | پردازش منطق برنامه         | Python, Node.js      |
| Database                   | ذخیره و بازیابی اطلاعات    | MySQL, PostgreSQL    |
فرض کن وارد سایت فروشگاهی شدی و روی دکمه «مشاهده محصولات» کلیک می‌کنی.

1. ا-Frontend: درخواست نمایش محصولات رو می‌فرسته.
    
2. ا-Nginx: درخواست رو دریافت و به Backend هدایت می‌کنه.
    
3. ا-Backend: درخواست رو پردازش می‌کنه و از Database اطلاعات می‌خواد.
    
4. ا-Database: اطلاعات محصولات رو به Backend برمی‌گردونه.
    
5. ا-Backend: نتیجه رو به Nginx می‌ده و Nginx به مرورگر برمی‌گردونه.
    
6. ا-Frontend: محصولات رو نمایش می‌ده.

----

## 2- حالا چرا از reverse proxy استفاده میکنیم

بهترین توضیحی که میشه داد

- چون می‌خوایم یک نقطه ورودی مشخص برای درخواست‌ها داشته باشیم و Backend رو مستقیماً در معرض اینترنت قرار ندیم.
- کاربر به `example.com` درخواست می‌فرسته.
    
- ا-Nginx درخواست رو دریافت می‌کنه.
    
- ا-Nginx درخواست رو به `127.0.0.1:3000` می‌فرسته.
    
- ا-Backend پاسخ می‌ده و Nginx اون رو به کاربر برمی‌گردونه.

---
## 3- و یکی از مهمترین قسمت هایه دیگه شبکه بک اند و ریورس پروکسی از دید کلاینت

- ا-<mark>Reverse Proxy</mark>: یک سرور با IP و Port قابل دسترسیه که Client مستقیماً بهش وصل می‌شه.<mark> public</mark>
    
- ا-<mark>Backend</mark>: یک سرور معمولاً داخل شبکه خصوصی که Client مستقیماً بهش وصل نمی‌شه و از طریق Reverse Proxy باهاش ارتباط داره.<mark> private</mark>

- پس همانطور که دیدید کللل فلسفه اینه که <mark> شبکه اون ریورسه پابلیکه و تنها جایی که کلاینت میتونه درخواست بزنه  و شبکه بک اند مخفی است و نمتونه مستقیم اون کلاینت درخواست بزنه </mark> 

نکته فنی: Client فقط با IP و Port مربوط به Reverse Proxy اتصال TCP برقرار می‌کنه. Reverse Proxy هم یک اتصال جداگانه به Backend ایجاد می‌کنه.

خلاصه: از دید Client، فقط Reverse Proxy قابل مشاهده و دسترسه و Backend پشت اون قرار داره، البته به شرطی که دسترسی مستقیم به Backend محدود شده باش

---

معمولاً Backend رو داخل شبکه خصوصی (Private Network) قرار می‌دن و Reverse Proxy رو در دسترس اینترنت می‌ذارن.

```
        Internet
           |
           v
    Reverse Proxy
    Public IP: 1.2.3.4
           |
           | Private Network
           v
        Backend
     10.0.0.10:3000
```

- ا-Reverse Proxy: از اینترنت قابل دسترسه.
    
- ا-Backend: فقط از شبکه خصوصی قابل دسترسه.
    
- ا-Firewall: می‌تونه طوری تنظیم بشه که فقط Reverse Proxy اجازه اتصال به Backend رو داشته باشه.
    

نکته مهم: صرفاً خصوصی بودن IP به این معنی نیست که فقط Nginx دسترسی داره؛ <mark> این محدودیت رو با Firewall اعمال می‌کنیم.</mark>
