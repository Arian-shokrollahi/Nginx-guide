# چی قراره بخونیم :
- مفهوم Event-based
- مفهوم event loop
- مفهوم non-blocking I/O
---
##### اول رویداد چیه؟
خیلی ساده، **رویداد (event) یعنی یک اتفاق که برنامه می‌تونه متوجهش بشه و بهش واکنش نشون بده.**

مثلاً:

- روی دکمه کلیک می‌کنی ← یک رویداد.
- پیامی دریافت می‌شه ← یک رویداد.
- کاربر به سرور وصل می‌شه ← یک رویداد.


---

#### به صورت خیلی ساده event-based چیست؟
برای درک بهتر، فرض کن سه کاربر به انجین‌ایکس وصل شدن:

- **کاربر اول:** هنوز داره درخواستش رو با اینترنت کند ارسال می‌کنه.
- **کاربر دوم:** درخواستش رسیده و آمادهٔ پردازشه.
- **کاربر سوم:** آماده‌ست پاسخ رو دریافت کنه.

پردازش کاری انجین‌ایکس کنار کاربر اول منتظر نمی‌مونه؛ به درخواست کاربر دوم رسیدگی می‌کنه و برای کاربر سوم پاسخ می‌فرسته. وقتی دادهٔ بیشتری از کاربر اول رسید، دوباره به اون رسیدگی می‌کنه.

- «هر اتصال که آمادهٔ خواندن یا نوشتن باشه، بهش رسیدگی می‌شه؛ انتظار برای دادهٔ یک اتصال، رسیدگی به بقیه رو متوقف نمی‌کنه.»
- به هرکدوم که اماده تره رسیدگی میکند لپ کلام

---
#### حالا این event based چجوری پیاده سازی میشه با  event loop که حالا بریم ببنیم که این event loop به چه صورت این کار را انجام میده

۱. پردازش کاری از سیستم‌عامل می‌پرسه کدوم اتصال‌ها آمادهٔ انجام کار هستن.

۲. سیستم‌عامل اتصال‌های آماده رو مشخص می‌کنه.

۳. پردازش کاری به رویدادهای اون اتصال‌ها رسیدگی می‌کنه؛ مثلاً داده می‌خونه یا پاسخ می‌فرسته.

۴. دوباره همین چرخه رو تکرار می‌کنه.

---
### و یه مفهوم دیگه هم اینجا مهمه به اسمه  non-blocking-I/O
اگر یک اتصال هنوز داده‌ای برای خواندن نداشته باشه، عملیات خواندن، پردازش کاری رو متوقف نمی‌کنه؛ برنامه می‌تونه سراغ اتصال‌های دیگه بره.

البته وقتی هیچ اتصال آماده‌ای وجود نداره، حلقه می‌تونه منتظر اعلام رویداد از سیستم‌عامل بمونه؛ لازم نیست دائماً اتصال‌ها رو بررسی کنه و پردازنده رو مشغول نگه داره.

**یک نکتهٔ کلیدی:** مدیریت هم‌زمان چند اتصال، لزوماً به معنی اجرای همهٔ کارها در یک لحظه نیست. یک پردازش کاری بین اتصال‌های آماده جابه‌جا می‌شه؛ وجود چند پردازش کاری هم امکان استفاده از چند هستهٔ پردازنده رو فراهم می‌کنه.

برای یادداشتت بنویس: **«انجین‌ایکس با حلقهٔ رویداد و عملیات شبکهٔ غیرمسدودکننده، تعداد زیادی اتصال را مدیریت می‌کند و هنگام انتظار یک اتصال برای داده، به اتصال‌های دیگر رسیدگی می‌کند.»**
