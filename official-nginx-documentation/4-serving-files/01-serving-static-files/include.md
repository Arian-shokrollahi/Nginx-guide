## بخش اول :
### ۱-۱ دلیل استفاده از این دایرکتیو چیه :
- فایل اصلی کانفیگ nginx  کجاست ---> etc/nginx/nginx.conf
- حالا اگر این فایل بخواد خیلی شلوغ و شلخته باشد بد میشه 
- حالا با استفاده از <mark>include directive</mark> شما میتونید یه کانفیگ کاملی که درون یک فایل در مسیر و فایل دیگه است رو بیارید درون اون کانفیگ فایل اصلیتون--->etc/nginx/nginx.conf/

### ۲-۱ یه توضیح رسمی تر :
- دایرکتیو `include` برای اینه که به‌جای نوشتن تمام تنظیمات یک فایل کانفیگ داخل فایل اصلی `nginx.conf`، فقط با یک خط و مشخص کردن آدرس اون فایل، تنظیماتش رو وارد کانفیگ اصلی کنیم.

### مثلا در مثال دایرکتیو قبلی که میخواستیم donky.png رو که فایل کانفیگش درون  etc/nginx/conf.d/images.conf/ بود اون رو بیاری تو قسمت و بلاک http  در فایل کانفیگ اصلی
```
# nginx.conf

http {
    include /etc/nginx/conf.d/images.conf;
}
```

- 2 اون موضوع اصلی که باعث میشه ما درون conf.d هرچی مینویسیم بیاد تو nginx.conf در بخش بلاک http

دایرکتیو `include` برای اینه که به‌جای نوشتن تمام تنظیمات یک فایل کانفیگ داخل فایل اصلی `nginx.conf`، فقط با یک خط و مشخص کردن آدرس اون فایل، تنظیماتش رو وارد کانفیگ اصلی کنیم.

مثلاً:

```
# nginx.conf

http {
    include /etc/nginx/conf.d/images.conf;
}
```

در این حالت، Nginx فایل `images.conf` رو می‌خونه و محتوای اون رو انگار مستقیماً داخل بلاک `http` نوشته شده، در نظر می‌گیره.
