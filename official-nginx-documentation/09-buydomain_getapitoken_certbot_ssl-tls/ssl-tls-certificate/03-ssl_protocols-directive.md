# ۱-اول اینکه **SSL و TLS چه ارتباطی با هم دارند؟**

ا-SSL پروتکل قدیمی‌تری است که امروزه منسوخ شده و TLS جایگزین آن شده است.

اما به دلایل تاریخی، هنوز در نام‌گذاری‌های Nginx از عبارت `ssl` استفاده می‌شود.

مثلاً:

```
listen 443 ssl;
```

اینجا کلمه `ssl` به معنی استفاده از پروتکل قدیمی SSL نیست؛ بلکه به Nginx می‌گوید این پورت برای ارتباط امن HTTPS با TLS پیکربندی شود.

---
# ۲-این دایرکتیو در کجا قرار میگیرد و ساختار ان به چه صورت است؟

### **محل قرارگیری دایرکتیو**

این دایرکتیو در کانتکست‌های زیر قابل استفاده است:

- ا-`http`
    
- ا-`server`
    

نکته: این دایرکتیو در کانتکست `location` قابل استفاده نیست.

### **۲. ساختار دایرکتیو**

ساختار کلی آن به شکل زیر است:

```
ssl_protocols protocol1 protocol2 ...;
```

در این ساختار، بعد از نام دایرکتیو، نسخه‌های TLS موردنظر را مشخص می‌کنیم.

مثال:

```
ssl_protocols TLSv1.2 TLSv1.3;
```

### **مثال در محیط Production**

معمولاً می‌توانیم این دایرکتیو را در کانتکست `server` مربوط به HTTPS قرار دهیم:

```
http {

    server {
        listen 443 ssl;
        server_name example.com;

        ssl_certificate /etc/nginx/ssl/fullchain.pem;
        ssl_certificate_key /etc/nginx/ssl/privkey.pem;

        ssl_protocols TLSv1.2 TLSv1.3;

        location / {
            proxy_pass http://backend;
        }
    }

}
```

## پارامتر ها ونسخه هایه TLS  که میتونیم استفاده کنیم و برسی انها:

## **نسخه‌های مختلف TLS**

|نسخه|وضعیت|
|---|---|
|SSL 2.0|منسوخ و ناامن|
|SSL 3.0|منسوخ و ناامن|
|TLS 1.0|منسوخ|
|TLS 1.1|منسوخ|
|TLS 1.2|امن و قابل استفاده|
|TLS 1.3|جدیدتر و پیشنهادی|

نکته: SSL و TLS دو پروتکل متفاوت از یک خانواده هستند. امروزه برای HTTPS از TLS استفاده می‌کنیم.

```
ssl_protocols TLSv1.2 TLSv1.3;
```

در این مثال، سرور فقط اجازه استفاده از دو نسخه را می‌دهد:

- TLS 1.2
    
- TLS 1.3
