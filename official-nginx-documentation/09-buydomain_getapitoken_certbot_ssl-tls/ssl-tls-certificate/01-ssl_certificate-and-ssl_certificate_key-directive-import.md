# ssl_certificate and ssl_certificate 
# ssl_certificate_key
# two important directive for set HTTPS protocol
---
# 1-تعریف این دایرکتیو به چه صورته؟


 - ا-`ssl_certificate`: برای تعیین مسیر فایل گواهی دیجیتال (SSL Certificate) استفاده می‌شود که شامل اطلاعات هویتی سرور و کلید عمومی آن است و برای احراز هویت سرور در ارتباط امن TLS به کار می‌رود.
    
- ا-`ssl_certificate_key`: برای تعیین مسیر فایل کلید خصوصی (Private Key) متناظر با گواهی SSL استفاده می‌شود که برای اثبات مالکیت گواهی و انجام فرایند رمزنگاری در ارتباط TLS به کار می‌رود.

---
# 2- ساختار این دو فایل به چه صورت است و هرکدوم این فایل ها چه چیزی رو نگه میدارند ؟

## 2-1**ساختار فایل fullchain.pem**

این فایل یک فایل متنی با فرمت PEM است که شامل گواهی دامنه و گواهی‌های واسط (Intermediate Certificates) است.

اگر محتویات آن را با دستور زیر ببینی:

```
sudo cat /etc/letsencrypt/live/domainname/fullchain.pem
```

ساختاری مشابه این مشاهده می‌کنی:

```
-----BEGIN CERTIFICATE-----
MIIFazCCA1OgAwIBAgISA...
...
...
-----END CERTIFICATE-----

-----BEGIN CERTIFICATE-----
MIIE... 
...
...
-----END CERTIFICATE-----
```

این فایل معمولاً دو بخش اصلی دارد:

**بخش اول: Domain Certificate**

گواهی‌ای است که برای دامنه خودت صادر شده و شامل اطلاعاتی مانند موارد زیر است:

- دامنه (Subject / SAN)
    
- صادرکننده گواهی (Issuer)
    
- تاریخ شروع اعتبار
    
- تاریخ انقضای گواهی
    
- Public Key
    
- امضای دیجیتال صادرکننده
    

**بخش دوم: Intermediate Certificate**

گواهی واسطی است که ارتباط زنجیره‌ای بین گواهی دامنه و Root CA را برقرار می‌کند.

به این ترتیب، کلاینت می‌تواند زنجیره اعتماد (Certificate Chain) را بررسی کند.

## 2-2 **ساختار فایل privkey.pem**

این فایل شامل Private Key یا کلید خصوصی دامنه است.

اگر محتویاتش را ببینی:

```
sudo cat /etc/letsencrypt/live/domainname/privkey.pem
```

ساختاری مشابه زیر مشاهده می‌کنی:

```
-----BEGIN PRIVATE KEY-----
MIIEvQIBADANBgkqhkiG9w0BAQE...
...
...
-----END PRIVATE KEY-----
```

این فایل شامل اطلاعات رمزنگاری‌شده مربوط به کلید خصوصی است.

وظیفه آن چیست؟

- نگهداری کلید خصوصی سرور
    
- اثبات مالکیت کلید متناظر با Public Key موجود در Certificate
    
- مشارکت در عملیات رمزنگاری مربوط به TLS
    

نکته مهم: در TLS مدرن، مانند TLS 1.2 با ECDHE و TLS 1.3، Private Key معمولاً برای امضای دیجیتال در Handshake استفاده می‌شود، نه رمزگشایی مستقیم ترافیک.

## 3-فایل هایه مورد استفاده برایه این دو دایرکتو رو از کجا بیاریم

یه نگاه به فایل درون این مسیر بندازید  [ssl certificate part four](../01-activation-domain_part4.md)
ما در اخر این فایل در مسیر etc/letsencrypt/live/domainname/ فایل هایی گرفتیم 

```
cert.pem  chain.pem  fullchain.pem  privkey.pem  README
```

و این فایل ها حالا در اینجا به کمکمون میان تابتونیم  HTTPS رو راه اندازی کنیم  اگر به مرحله ۲ نگاه کنید در ساختار از این فایل ها استفاده شده اون مسیری که ذخیری میشه مهم نیست شما میتونید تو هر مسیری انتخاب کنید بره اون فایل ها ولی معمولا در مسیر etc/letsencrypt/live/domainname/ میذارن اون فایل هارو 

---
# 4-نکات برایه جمع بندی


حالا این فایل‌ها در پیکربندی HTTPS به کمک ما می‌آیند.

در واقع، برای دو دایرکتیوی که معرفی کردیم، از این دو فایل استفاده می‌کنیم:

- ا-`fullchain.pem` برای دایرکتیو `ssl_certificate`
    
- ا-`privkey.pem` برای دایرکتیو `ssl_certificate_key`
    

نکته: مسیر `/etc/letsencrypt/live/domainname/` مسیر استانداردی است که Certbot برای نگهداری گواهی‌های دامنه استفاده می‌کند. شما از نظر فنی می‌توانید گواهی‌ها را در مسیر دیگری نیز قرار دهید، اما در استفاده از Certbot بهتر است از همین مسیر استاندارد استفاده کنید؛ زیرا فایل‌های این مسیر به نسخه‌های اصلی گواهی در پوشه `archive` اشاره می‌کنند و هنگام تمدید گواهی، به‌روزرسانی می‌شوند.

**نکته امنیتی:** فایل `privkey.pem` حاوی کلید خصوصی است و نباید در اختیار افراد غیرمجاز قرار بگیرد یا در مخازن عمومی GitHub بارگذاری شود.
